# Переезд на свой сервер в России

**Зачем.** По 152-ФЗ (ч. 5 ст. 18) персональные данные граждан РФ — имена и телефоны из
заявок — записываются и хранятся в базах на территории России. Vercel и Neon находятся
за рубежом, поэтому до приёма настоящих заявок сайт переезжает на сервер в российском
дата-центре.

**Что получится.** Тот же сайт и админка, но на своём сервере:

- код подтягивается из GitHub сам каждые 5 минут — как на Vercel: изменения влиты в `main`, через 5–15 минут они на сайте;
- новая версия включается, только если собралась и отвечает; иначе работает прежняя, а в Telegram приходит сообщение (если настроен бот, `TELEGRAM_*`);
- HTTPS от Let's Encrypt, сертификат продлевается сам;
- копия базы каждую ночь, хранятся 14 последних.

Всё это ставит один скрипт — [deploy/install.sh](deploy/install.sh); управление — командой `tarify` ([deploy/tarify.sh](deploy/tarify.sh)).

---

## 1. Сервер

Любой VPS с дата-центром в России: Timeweb Cloud, Selectel, REG.RU, Beget и другие.

- **Ubuntu 24.04** (подойдёт и 22.04);
- **2 vCPU, 2–4 ГБ памяти, от 30 ГБ диска**;
- публичный IPv4-адрес.

Доступ — root: пароль обычно приходит на почту, консоль есть в панели хостинга (работает и
из браузера на телефоне).

## 2. Установка — около 15 минут

Откройте консоль сервера: в панели хостинга или по SSH (`ssh root@IP-сервера`). Если вошли
не под root — сначала выполните `sudo -i`.

**Шаг 1. Ключ для GitHub.** Сервер берёт код из закрытого репозитория по своему ключу:

```bash
apt-get update && apt-get install -y git
install -d -m 700 /root/.ssh
[ -f /root/.ssh/tarify_deploy ] || ssh-keygen -t ed25519 -N "" -C tarify-server -f /root/.ssh/tarify_deploy -q
cat /root/.ssh/tarify_deploy.pub
```

Скопируйте выведенную строку `ssh-ed25519 …` и добавьте её на GitHub: репозиторий
**Silence2111/tarify → Settings → Deploy keys → Add deploy key**. Название — любое, например
«server»; галочку **Allow write access** не ставьте; **Add key**.

**Шаг 2. Код и установка:**

```bash
GIT_SSH_COMMAND="ssh -i /root/.ssh/tarify_deploy -o StrictHostKeyChecking=accept-new" git clone git@github.com:Silence2111/tarify.git /opt/tarify/repo
bash /opt/tarify/repo/deploy/install.sh
```

Установщик спросит две вещи:

1. **Домен сайта** — например, `tarify.rumedia-cdn.com`.
2. **Строку подключения к нынешней базе**, чтобы перенести данные: Vercel → проект →
   Settings → Environment Variables → `DIRECT_URL` (значок глаза → скопировать). Нажмите
   Enter, если переносить нечего, — сайт начнёт с демо-данных.

Остальное установщик делает сам: Node.js 22, PostgreSQL 17, nginx, база с паролем, сборка
сайта, перенос данных, автообновление, ночные копии базы. Запускать его повторно безопасно.

**Шаг 3. Настройки из Vercel.** Токены, реквизиты и счётчики (`POSTBACK_TOKEN`,
`TELEGRAM_*`, `OPERATOR_*`, `PD_RECIPIENTS`, `NEXT_PUBLIC_YANDEX_METRIKA_ID`,
`LEAD_WEBHOOK_URL`…) переносятся одной командой:

```bash
tarify env --paste
```

Вставьте строки вида `КЛЮЧ=значение` — по одной на переменную из Vercel, в конце — пустая
строка. Сайт пересоберётся сам. Строки подключения к базе (`DATABASE_URL`, `DIRECT_URL`)
команда пропускает: у сайта на сервере своя база.

Пароль админки переносить не нужно: он в коде (хэшем) и остаётся прежним.

## 3. Проверка до переключения домена

- Откройте `http://IP-сервера` — должна открыться главная страница сайта.
- `tarify status` — версия сайта, автообновление, копия базы.
- Админка по IP не впустит: cookie входа работает только по HTTPS. Её проверка — после шага 4.

## 4. Переключение домена и HTTPS

1. Перенесите данные ещё раз прямо перед переключением, чтобы не потерять заявки,
   пришедшие на Vercel за это время:
   `tarify import-db 'строка DIRECT_URL из Vercel'`.
2. В DNS домена (у регистратора `rumedia-cdn.com` или там, где управляются его записи)
   замените запись `tarify`: вместо CNAME на Vercel — **A-запись на IP сервера**.
3. Через 10–30 минут выполните `tarify https` — команда проверит, что домен уже указывает
   на сервер, выпустит сертификат и включит HTTPS.
4. Откройте сайт и войдите в админку по `https://`.

## 5. После переезда

- **Vercel:** удалите домен из проекта (Settings → Domains), затем сам проект — чтобы старая
  версия сайта не принимала заявки по адресу `*.vercel.app`.
- **Neon:** удалите базу — после переезда персональные данные не должны оставаться за
  рубежом.
- **Роскомнадзор:** в уведомлении об обработке персональных данных укажите, где находится
  база, — город и адрес дата-центра хостинга.

## Повседневные команды

Все — от root на сервере.

| Команда | Что делает |
|---|---|
| `tarify status` | версия сайта, автообновление, последняя копия базы, свободное место |
| `tarify update` | обновиться сейчас (само — каждые 5 минут) |
| `tarify update --force` | пересобрать и без новых коммитов |
| `tarify rollback` | вернуть предыдущую версию |
| `tarify env` | какие переменные заданы; `tarify env КЛЮЧ` — значение одной |
| `tarify env КЛЮЧ значение` | задать переменную и пересобрать сайт; `tarify env КЛЮЧ ""` — удалить |
| `tarify backup` | копия базы сейчас (сама — каждую ночь в 3:30, хранятся 14 последних) |
| `tarify import-db СТРОКА` или `ФАЙЛ` | заменить базу копией другой базы или файлом из `/var/backups/tarify` |
| `tarify logs`, `tarify logs -f` | журнал сайта и обновлений |

Копии базы лежат в `/var/backups/tarify` на том же сервере. На случай поломки самого
сервера включите в панели хостинга снимки диска или время от времени скачивайте копию к
себе: `scp root@IP-сервера:/var/backups/tarify/ИМЯ-ФАЙЛА .`

## Если что-то пошло не так

- **Новая версия не включилась** — сайт работает на прежней, причина в `tarify logs`. После
  исправления в GitHub новая версия подтянется сама; `tarify update --force` — попробовать
  сразу.
- **Нет доступа к GitHub** — `tarify status` покажет ключ сервера: добавьте его в
  Deploy keys репозитория.
- **Не скачиваются пакеты npm или Prisma** — серверу нужен доступ к `registry.npmjs.org` и
  `binaries.prisma.sh`; у некоторых хостингов исходящие соединения ограничены в панели.
- **`tarify https` пишет, что домен указывает не туда** — DNS ещё не обновился: подождите и
  повторите.
